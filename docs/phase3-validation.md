## Reproduction before / fix after

The final primary regression module was copied into an isolated source snapshot of exactly `38182e24fad2be25c0e6ffcfe5c78d10573d4f6c`. No old-branch application code was edited. Running only the four SIGINT cases and six result-protocol cases produced **10 failed, 11 deselected** at that point in the test additions. The four lifecycle failures observed a descendant still running; the MIME array raised TypeError and other protocol cases accepted invalid output. The final implementation passes all ten cases within its 114-test suite.

The lifecycle tests deliver real SIGINT synchronously at each selected native-signal boundary. They exercise both a live direct worker and a leader that has already exited while a TERM-resistant descendant remains. They verify the original KeyboardInterrupt object propagates, the direct worker PID is gone, the descendant actually stops via bounded `/proc` polling, the job directory is removed, and a new real PDF merge reuses capacity. These are deterministic boundary probes, not claims about natural SIGINT frequency. SIGKILL delivery is asynchronous, so a successful signal call alone is not treated as proof of descendant exit. Linux subreaper state is restored and adopted probe descendants are explicitly reaped, even when testing the broken baseline.

Follow-up review caught and prompted additional red/green regressions: final close must not replace the original interruption; TERM ESRCH must not be followed by a signal to a potentially reused numeric group; successful Windows CloseHandle plus pending SIGINT must not replay the released handle; directory cleanup failure must preserve an active interruption; and an exception already caught by a caller must not turn this job's cleanup failure into success. Those cases failed before their corrections and pass afterward. Cleanup failure notes record additional failures while an interruption is already propagating; cleanup failure on an otherwise successful job remains an error.

The Windows cases simulate APIs and inject actual Python SIGINT around the simulated close side effect. They test control flow, retained-handle state and restoration of the original signal handler. They do not execute Win32, prove native handle validity, verify nested jobs or establish that all descendants complete termination before directory removal.
